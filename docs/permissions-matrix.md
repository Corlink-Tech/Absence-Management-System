# ماتریس نقش‌ها و مجوزها

## قواعد اجباری

- هر endpoint، object و فایل، مالکیت فرد، شرکت فعال در زمان مربوط، نقش و محرمانگی را سمت سرور بررسی کند.
- تغییر id در URL، فیلتر، body، export یا شناسهٔ فایل نباید scope را گسترش دهد.
- UI هیچ‌گاه مرجع مجوز نیست؛ payload برای کاربر غیرمجاز اساساً نباید شامل داده محرمانه باشد.
- حساب غیرفعال/پایان‌یافته قادر به ورود نیست؛ تغییر نقش یا manager در درخواست‌های جدید فوراً مؤثر است.
- manager ثبت‌شده روی درخواست snapshot می‌شود؛ سیاست تصمیم‌گیر برای درخواست تاریخی و انتقال سازمانی باید HR تصویب کند.
- مدیر سامانه به‌دلیل توان مدیریت سیستم، مجاز خودکار به خواندن دلیل پزشکی یا پیوست نیست.
- دسترسی اضطراری (break-glass) نیازمند دلیل، زمان انقضا، ثبت حسابرسی و بازبینی مستقل است؛ تا تصویب سیاست غیرفعال.
- سیاست نمایش غیبت به همکار، خروجی، اعلان و تقویم باید یکسان و fail-closed باشد. نوع محرمانه حتی در payload کم‌مجوز نیز حذف/خنثی شود.
