# امنیت و حفاظت داده

این سند threat model اولیه است، نه ممیزی امنیتی یا ادعای انطباق حقوقی. گزارش‌های منبع هیچ آسیب‌پذیری قطعی اعلام نکرده‌اند؛ موارد Excel با شناسه SEC اولویت آزمون هستند.

## دارایی‌ها و تهدیدها

| دارایی/تهدید | کنترل لازم | آزمون پذیرش |
|---|---|---|
| حساب، نشست و نقش | هش رمز با الگوریتم معتبر Django، cookieهای Secure/HttpOnly/SameSite، CSRF، انقضا و لغو نشست | ورود حساب غیرفعال/جلسه منقضی رد شود؛ CSRF نامعتبر رد شود |
| درخواست و اطلاعات شخصی | مجوز object-level، scope شرکت در query، allowlist فیلد، rate limit | IDOR با تغییر id در API/گزارش/پیوست موفق نشود |
| داده پزشکی/نوع محرمانه | کمینه‌سازی payload، scope HR، حذف از ایمیل/تقویم/export عمومی و log | تلاش خواندن با حساب کارمند/مدیر/مدیر سامانه رد یا داده خنثی برگرداند |
| سهمیه و رقابت هم‌زمان | تراکنش، قفل ردیف، نسخه/شرط وضعیت و idempotency | دو تصمیم هم‌زمان دوباره‌کاری/کسر دوگانه نسازد |
| ورودی متنی و API | serializer validation، ORM پارامتری، output encoding، محدودیت طول و rate limiting | payload بدشکل/XSS/SQL-like متن به کد/SQL تبدیل نشود |
| پیوست | نوع و اندازه allowlist، بررسی محتوای فایل، نام تصادفی، ذخیره خصوصی، عدم اجرا، دانلود مجوزدار | کاربر غیرمجاز با URL مستقیم یا تغییر id فایل نتواند دریافت کند |
| خروجی spreadsheet | فرار از سلول‌های دارای `=`, `+`, `-`, `@` و کنترل quoting/encoding | فایل آزمون در Excel/LibreOffice فرمول اجرا نکند |
| secrets/زیرساخت | Environment/secret store، DB حداقل‌دسترسی، TLS، image pin/scan | اسکن repo/log/image فاقد secret باشد؛ سرویس DB عمومی نباشد |
| Job و ایمیل | دسترسی حداقل، idempotency، retry محدود و log پالایش‌شده | اجرای تکراری ارسال/تغییر دوباره نکند؛ متن محرمانه به مخاطب نامجاز نرسد |
| backup | رمزگذاری در storage، دسترسی محدود، چرخه نگهداری مصوب و restore drill | بازیابی در محیط جدا و تطبیق شمارنده/نمونه داده ثبت شود |

## اصول داده و audit

- ذخیره و پردازش حداقل اطلاعات ضروری؛ اسناد پزشکی فقط در صورت نیاز و با سیاست نگهداری مصوب.
- audit append-only در سطح برنامه/DB؛ تغییر policy و عملیات حساس actor، زمان، scope، entity، نتیجه و دلیل پالایش‌شده دارند.
- رمز عبور، session id، token، کلید خصوصی و متن پزشکی/آزاد کامل وارد log نمی‌شوند. به‌جای متن، شناسه رویداد و مقدارهای غیرحساس ثبت شود.
- audit trail جایگزین policy حذف قانونی نیست؛ retention، legal hold و حذف/ناشناس‌سازی باید پیش از بهره‌برداری با مسئول داده تصویب شود.
- مدیر فنی به صورت پیش‌فرض نباید متن پزشکی را بخواند؛ دسترسی اضطراری فقط با policy، ثبت و بازبینی.
- هشدار overlap/تقویم/پیام به جانشین فقط حداقل اطلاعات لازم و بدون علت یا سند پزشکی را منتشر می‌کند.

## کنترل‌های انتشار

تست مجوز نقش/مالکیت/شرکت برای هر endpoint، وابستگی‌ها و secret scanning، lint/typecheck/test، dependency lock، migration review، پیکربندی HTTPS، محدودیت rate، بازبینی log و اجرای restore drill لازم است. بررسی penetration باید توسط مسئول انسانی مجاز و در محیط مجاز انجام شود. ریسک‌ها SEC-001 تا SEC-007 مرجع آزمون‌اند، نه findings تأییدشده.
