## مغایرت‌ها و کیفیت شواهد

- Excel پنج شیت، DOCX سه‌گانه، README و SPECIFICATION بررسی شدند. گزارش فنی صریحاً می‌گوید checkout، بررسی خط‌به‌خط کد، اجرای تست و تست نفوذ انجام نشده است.
- README/SPECIFICATION بعضی قابلیت‌ها را با زبان «built/implemented» معرفی می‌کند؛ DOCX و Excel فهرست قابلیت‌ها را «مستندشده، نیازمند آزمون عملی» می‌نامند. وضعیت محصول مستقل در همه موارد «پیاده‌سازی‌نشده» است.
- XLSX موارد SEC-001 تا SEC-007 را finding قطعی نمی‌داند. شدت High برای اولویت آزمون است، نه اثبات آسیب‌پذیری.
- مرجع درباره کار روزانه دستی، تعطیلات دستی، split سالیانه و گونه‌های مختلف نمایش اطلاعات جزئیاتی دارد که باید با سیاست‌های سازمان تطبیق یابد؛ هیچ موردی بدون تصمیم مالک تبدیل به قانون داخلی نمی‌شود.
- گزارش Word به عدم بازیابی تصاویر و عدم تولید Data Dictionary/OpenAPI از کد اشاره دارد؛ این workspace نیز کد/تصویر اجرایی برای تأیید در اختیار ندارد.

## پیش‌نیاز حکمرانی قبل از کدنویسی اجرایی

AGENTS.md توصیه می‌کند برای تغییرات چندزیرسامانه‌ای/تصمیم معماری، ابتدا تیکت بحث با نگه‌دارندگان ثبت شود. تبدیل این مخزن از افزونه Nextcloud به سامانه مستقل، تغییر دامنه و معماری است؛ تصمیم درباره مخزن/مالکیت/انتقال repository و سیاست license نیز باید روشن باشد. عامل نباید تیکت یا PR را به‌جای انسان ارسال کند. این مجموعه سند مرحله تحلیل و طراحی است، نه مجوز خودکار برای حذف یا جایگزینی محصول فعلی.
